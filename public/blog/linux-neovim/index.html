Thoughts on Linux, Neovim, Hyprland, etc.

October 4, 2026

I started tinkering with Linux (and the rest of my computer) during the COVID lockdown (like may others, I gather). My first thought was, “I want to be cool” (I was like 13 at the time) so I tried Arch first. Of course Arch Linux installation isn’t the easiest thing (especially for a dumb 7th grader) so of course I bricked my system (probably). Fortunately I had a full backup of my disk and I learned to start with something more manageable first.

The distributions I use has, I think, been: Ubuntu (didn’t like Gnome) → Kubuntu → KDE Neon → Fedora (too lazy to deal with package managers) → EndeavourOS (basically Arch) → Arch (since around 2023?). I exclusively used KDE Plasma, which is (in my opinion) the best-looking (out of the box) desktop environment with plenty of modern features (KDE software suits is great). I eventually wanted to use a tiling window manager for no good reason really and switched to using Hyprland.

I am not going to smugly tell you how I am superior and enlightened and you’re a normie for not using Linux. Quite the opposite. Some reasons people often say they use Linux include: to support free and open source software, because they do not like Microsoft/Apple, because the NSA has backdoors in Windows (I mean, probably), etc. I agree, to some extent, with all of this. But I think the stronger reasons why I keep using Linux are not ideological. In my opinion, the ways in which Linux is more convenient than Windows outweigh the ways in which it is not:

  • Command line interface: yes, this is scary at first, but it is incredibly useful. One can do many things faster in the CLI than the GUI. Not having to open a new window is a plus as well for efficiently purposes. For example: file navigation, interacting with files, executing programs, etc. are all, in my opinion, faster in the Linux command line than the Windows GUI.
  • Packages and upgrades: Windows has nothing comparable to this. Chocolatey, winget, etc do not come close to things like APT, pacman, the Arch User Repository, etc. In my view it is far more convenient to search up a package and install it in the command line than to navigate through the web page, download, install, etc… Of course, system upgrades are easier too, simply pacman -Syu or yay on Arch.
  • It just works: you may have seen memes like “Linux users installing a web browser” (people tell me this all the time). This is not true. As above it is just as easy, if not easier, to install applications (which support Linux, of course), to install things on Linux as Windows. For example, you can install the chromium web browser in just one command: pacman -S chromium.
  • Development is easier on Linux than Windows: there really should be a version of the meme above about “Windows users installing a C compiler”. It’s really quite a process on Windows: you have to install MinGW/Cygwin (which, ironically, use the pacman package manager from Arch), set up a bunch of environment variables, etc. Not even to say that Windows is not Unix-like, which is really annoying: its ABI and API are different from standard Unix, different filesystems, commands, etc. It runs on the NT architecture which is completely different from POSIX/*nix. This is not really a problem from regular users but it is quite annoying for developers, and Microsoft introduced Windows Subsystem for Linux to help with this.
  • Customizability: this is pretty obvious, but in Windows and MacOS there is no freedom to customize your own system. You really just have to accept whatever Microsoft or Apple gives you, which is really not a big deal for most people. That’s completely fine. But in some sense you can be said to not be completely “in control” of your own computer, and to me, being able to do whatever I want with my computer is fairly important. This might sound ideological but it really isn’t for reasons I’ll talk about below.

I’ve only really talked about Windows here. I know MacOS exists and that it’s Unix-like (not fully POSIX compliant) and addresses a lot of the issues above, but I really, really do not want to purchase a “MacBook.” I had one for a while, and I did not like the experience. The biggest issue to me was the customizability piece.

A couple of things that are worse on Linux: less apps (no Adobe apps, Microsoft office, for example), and the system does occasionally break itself. I’ve had system upgrades break the bluetooth driver and I’ve had to manually fix a situation where the EFI partition ran out of space (this required repartitioning and regenerating the fstab). When I first came to Harvard, the Harvard eduroam wifi authentication system did not work and I spent a few hours dealing with it. Eventually the solution was: to use wpa_supplicant instead of iwd, and use NetworkManager’s builtin DHCP client instead of dhcpcd. When I tell people about this they look at me like I’m crazy, which yeah it kind of is. One cannot honestly say in good faith that it is “as easy” as Windows or that “no software experience” is needed.

It’s definitely an individual division, and these tradeoffs are more than acceptable for me.

On customizability: note that I haven’t said anything about “bloat,” user interface, etc. The aesthetics of your system, which desktop environment or window manager you choose to use, your preferred kernel, number of apps, packages, which specific packages, etc. are all up to you. Absolutely not true on Windows or MacOS!

I chose to switch from KDE to Hyprland because I wanted a more minimal experience: KDE is fantastic, but I wasn’t using a lot of its features. I didn’t really need to move windows around, in fact I found it more convenient for them to tile automatically! Neither did I really “need” KDE’s extensive software suite (although it would really be helpful sometimes). So I switched to Hyprland and spent a week or so finding all the apps I need.

Similar with neovim: VS code is a good editor, and of course there are ideological reasons not to use it (to wit, not liking Microsoft, not liking that the binaries are closed source, etc.). VS code is highly customizable, unlike a certain other Microsoft product. So why do I use neovim? Uhh, it’s pretty cool, I guess. Vim keybindings are extremely useful and everyone should learn it. They make editing much faster to a degree you won’t really understand until you try it yourself, especially for code. If you (quite sensibly) don’t want to use (neo)vim, you can always get the neovim extension for VS code. I’m hearing that some people on my old robotics team don’t know how to turn it off, just as they may not know how to exit vim itself.

Anyway, I just wanted to write this to express some of my thoughts on why I use these tools/apps/operating systems ("…GNU/Linux, or as I’ve recently taken to calling it…"). To summarize, I find the ideological arguments for Linux somewhat compelling, but there are legitimate, non-ideological reasons to use Linux. You never really know what you’d like to customize on your system until you use something that doesn’t force you into a certain design choice. Freedom is a beautiful thing, I think. I feel similar about using a tiling window maanger or using neovim for some/most of my tasks: you might like it more than what you use, or you might not.
